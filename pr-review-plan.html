PR Review Pipeline

A GitHub-triggered, multi-agent review system: four specialist lenses run in parallel on every PR, verified findings post inline, low-confidence ones wait for a human — with every decision logged for audit.

01 Architecture

One PR event becomes one checkpointed graph run: fan out to four agents, verify each finding, then either post it, queue it for a human, or drop it silently.

02 Components

03 Core contracts

Every lens returns the same shape; every VCS host implements the same port. This is what makes a Bitbucket adapter a later addition, not a rewrite.

class Finding(BaseModel):
    path: str
    line: int
    side: Literal["LEFT", "RIGHT"]
    category: Literal["security", "quality", "test_coverage", "docs"]
    severity: Literal["low", "medium", "high"]
    confidence: float
    rationale: str
    suggested_patch: str | None = None
    fingerprint: str  # hash(path, normalized_snippet, category) — not line number

class VCSProvider(Protocol):
    async def fetch_diff(self, repo, pr_number) -> Diff: ...
    async def fetch_file(self, repo, path, ref) -> str: ...
    async def post_review(self, repo, pr_number, findings: list[Finding], summary: str) -> None: ...
    async def resolve_comment(self, repo, pr_number, comment_id) -> None: ...

04 Key decisions

01

One confidence gate, not two core

Verify assigns a confidence score once. Routing — auto-post, HITL, or discard — is a pure function of that number. No second, independent "is this good enough" check downstream to fight it.

02

HITL re-anchoring rule blocking

A push between queueing and approval can invalidate a finding's line. On approval: re-anchor by fingerprint against the current diff — post normally if the line still exists, else fall back to a file-level note in the summary. Never post against a stale head_sha.

03

interrupt() must not block a worker blocking

The ARQ job returns the moment the graph hits interrupt() — the checkpoint persists, not the job. Approval enqueues a fresh job that resumes the same thread, so worker concurrency stays bounded regardless of how long a human takes.

04

Idempotent post node core

ARQ retries and LangGraph checkpoint replay are two separate durability layers. The post node re-checks the findings table by (repo, pr_number, head_sha, fingerprint) immediately before writing — a retried job must not double-post a review.

05

Docs agent is gated

Fires only when the diff touches public API surface, config schema, CLI flags, or files referenced by README/docs. An unconditioned "update your docs" comment on every PR is how bots get muted.

06

Hypertable stores metrics, not payloads

model, input_tokens, output_tokens, latency_ms, agent, repo, pr_number, ts, decision — no raw diffs or completions by default. A capture flag exists for that, off by default, with its own retention policy if ever enabled.

07

Outcome tracking is data capture only v1 scope

v1 records PR outcome (merged/closed) and comment resolution (resolved/dismissed). Using that data to adjust agent behavior — confidence recalibration, prompt tuning — is deferred to v2.

08

Dashboard is a privileged component

It exposes cost/telemetry and, via the HITL endpoint, lets someone decide what gets posted to an org's PRs. Requires auth, authorization, and an ownership check — an approver must be scoped to the specific repo/installation they're approving for.

09

RAG only, no call-graph table v1 scope

The impact/blast-radius agent was dropped from v1. Quality covers correctness informally using diff + pgvectorscale-retrieved related code, not exact caller graphs.

10

Models referenced by config key

AGENT_MODEL_SECURITY, _QUALITY, _TEST_COVERAGE, _DOCS, _VERIFY — default claude-sonnet-5 for the four lenses, claude-haiku-4-5 for verify. Configurable per org, never hardcoded.

06 Phasing

Phase 1 — ships first
  • Webhook, HMAC verify, GitHub App auth
  • ARQ queue + LangGraph graph, full HITL interrupt/resume
  • All four lens agents on diff + on-demand Contents API fetch (no RAG yet)
  • Audit hypertable + outcome capture live from day one
✓ done when: a correct inline comment lands on a real PR, and a HITL-approved finding re-anchors correctly after a push
Phase 2
  • pgvectorscale index — backfill on install, incremental update on push
  • Lens agents upgraded to use RAG context
  • Custom dashboard app on top of the continuous aggregates

07 Verification

The bar is behavioral, not "tests pass" — comment anchoring is the highest-risk part of this build.

Unit tests: HMAC verification, fingerprint stability across line shifts, idempotent post node under retry

Real test PR with a planted bug, security issue, and untested change — every finding lands as an inline comment on the correct line, in one batched review

Push a second commit after a finding is HITL-queued; approve it; confirm re-anchoring posts correctly or falls back to the summary body
